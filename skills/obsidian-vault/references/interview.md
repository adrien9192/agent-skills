# Recorded memory interview

Use only for an explicitly requested interview or missing context in onboarding. Ordinary task
execution must not turn into an unsolicited questionnaire.

## Open and record

Read the relevant hub first. Choose one subject and decision horizon. Default to five questions,
one per turn; honor a smaller requested limit. An onboarding intake may use seven. After the
limit, close with knowns and unknowns; more questions require the user to continue the interview.

Use `50-Inbox/YYYY-MM-DD-<project>-interview-<topic>.md`. Reuse an existing note only when resuming
that exact interview. Otherwise choose a distinct suffix; do not overwrite another session.
Reuse a valid flat template: `type: knowledge`, `status: draft`, `project`, `source`, `created`,
`updated`, `verification: INSPECTED`, `tags`. Here INSPECTED means the recorded statements were
read, not that their business claims were externally verified. The note body states this limit.
Do not create new frontmatter keys for participants or question numbers; put them in the body.

1. Write the first precise question in the note, then ask it. Do not wait until the end to save it.
2. On a reply, append the useful answer, date and speaker immediately, preserving uncertainty,
   negation, amounts, scope and decision ownership. Quotes are exact; a paraphrase is labeled.
3. Only then append and ask the next question. Inspect an accessible source instead of asking
   the user to retrieve it. A summary in the daily log does not replace the Q/A record.
4. Re-read after each mutation. If saving fails, report it and do not claim the answer is stored.

Example: “1200 EUR is an idea; Marc must approve it” remains a proposed amount with Marc as
owner. It must not become an approved budget in the hub. Omit secrets, credentials and irrelevant
sensitive details from the transcript; say that a sensitive value was intentionally not stored.

## Stop and reconcile

“Stop”, “termine”, “pause”, refusal or the question limit closes the active interview immediately.
Save any answer in the stopping message first. Do not add one last question or request permission
to stop. On resume, read the saved note and pending point rather than repeat all questions.

Append a closure section with:
- up to five genuinely new facts or decisions; never pad to five;
- source and confidence/status for each, distinguishing declarations from observations;
- open points and their decision owner (unknown if not supplied), plus deadline only if known;
- one next useful action, or explicitly none.

Promote only durable supported items to the existing hub. A decision conflicts with an older
one: preserve the history, mark the replaced decision and update the CURRENT summary, not just
an appended journal. Unknowns remain unknown; a hypothetical number never overwrites an approved
one. Link the interview from the hub or daily entry so it can be found. Do not promote a raw
client transcript into shared cross-project knowledge. No deletion or publication at closure.
